# Объяснение: Почему не все органы отображаются в анализе чувствительности

## Проблема

В результатах анализа чувствительности отображаются не все органы защиты. Из 32 органов, для которых рассчитаны уставки, только 8 имеют результаты анализа чувствительности.

## Причины

### 1. Блокирующие органы (БЛОК) не проверяются на чувствительность

**Органы, которые пропускаются:**
- `3I0 БЛОК` - блокирующий орган по току нулевой последовательности
- `I2 БЛОК` - блокирующий орган по току обратной последовательности
- `IЛ БЛОК` - блокирующий орган по фазному току
- `U2 БЛОК` - блокирующий орган по напряжению обратной последовательности
- `DI1 БЛОК` - блокирующий орган по приращению тока прямой последовательности
- `DI2 БЛОК` - блокирующий орган по приращению тока обратной последовательности

**Почему они не проверяются:**
Блокирующие органы используются для **блокировки** других органов защиты, а не для прямого отключения. Они не имеют собственной логики проверки чувствительности, так как их функция - предотвратить ложные срабатывания других органов.

**Пример из логов:**
```
[DEBUG] Пропущен орган 3I0 БЛОК: нет обработчика чувствительности
[DEBUG] Пропущен орган I2 БЛОК: нет обработчика чувствительности
[DEBUG] Пропущен орган IЛ БЛОК: нет обработчика чувствительности
[DEBUG] Пропущен орган U2 БЛОК: нет обработчика чувствительности
```

### 2. Органы без записей в карте чувствительности

**Органы, которые отсутствуют в `SENSITIVITY_FAULT_MAP`:**
- `X ОТВ` - орган по реактивному сопротивлению (ответвления)
- `X ОТКЛ` - орган по реактивному сопротивлению (отключение)

**Почему они не проверяются:**
Эти органы не имеют записей в карте `SENSITIVITY_FAULT_MAP` в файле `sensitivity_fault_map.py`. Метод `_get_handler()` возвращает `None` для органов, которых нет в карте, и они пропускаются.

**Пример из логов:**
```
[DEBUG] Пропущен орган X ОТВ: нет обработчика чувствительности
[DEBUG] Пропущен орган X ОТКЛ: нет обработчика чувствительности
```

### 3. Органы с явно отключенной проверкой чувствительности

**Органы, для которых `check_sensitivity: False`:**
- `УГОЛ БЛОК` - орган сравнения фаз

**Почему он не проверяется:**
В карте `SENSITIVITY_FAULT_MAP` для этого органа явно установлено `check_sensitivity: False`:

```python
"УГОЛ БЛОК": {
    "description": "Орган сравнения фаз",
    "check_sensitivity": False,  # Не проверяется
},
```

**Пример из логов:**
```
[DEBUG] Пропущен орган УГОЛ БЛОК: нет обработчика чувствительности
```

## Органы, которые проверяются на чувствительность

Следующие органы **имеют** обработчики чувствительности в коде:

1. **РТНП/3I0_M0** - Реле направления мощности нулевой последовательности по току
2. **РННП/3U0_M0** - Реле направления мощности нулевой последовательности по напряжению
3. **3I0 ОТКЛ** - Орган по току нулевой последовательности (отключение)
4. **I2 ОТКЛ** - Орган по току обратной последовательности (отключение)
5. **IЛ ОТКЛ** - Орган по фазному току (отключение)
6. **R ОТВ** - Орган по активному сопротивлению (ответвления)
7. **R ОТКЛ** - Орган по активному сопротивлению (отключение)
8. **U2 ОТКЛ** - Орган по напряжению обратной последовательности (отключение)
9. **К МАН** - Орган манипуляции

**⚠️ ВАЖНО:** Наличие обработчика не гарантирует, что орган будет отображаться в интерфейсе. Для отображения необходимо, чтобы:
1. Для органа были найдены соответствующие КЗ в PowerFactory
2. Анализ чувствительности был успешно выполнен
3. Результаты были сохранены в БД (таблица `SensitivityAnalysis`)

## Почему органы не отображаются в интерфейсе

### Основная причина: отсутствие КЗ для анализа

Из логов видно, что для многих органов анализ чувствительности **не выполняется**, потому что **не найдены соответствующие КЗ**:

**Примеры из логов:**
```
[DEBUG] После исключения ответвлений: 0 КЗ (было 2)
[DEBUG] Обработка всех КЗ (0 шт.) для I2 ОТКЛ
[DEBUG] Обработка всех КЗ (0 шт.) для IЛ ОТКЛ
[DEBUG] Обработка всех КЗ (0 шт.) для U2 ОТКЛ
[DEBUG] Обработка всех КЗ (0 шт.) для К МАН
[WARNING] Не найдены значения 3I0 для расчета чувствительности 3I0 ОТКЛ на противоположной стороне
```

### Почему не найдены КЗ?

1. **Ошибки многопоточности PowerFactory:**
   - PowerFactory требует однопоточный режим
   - При многопоточности расчеты КЗ не выполняются
   - В логах: `[ERROR] Ошибка многопоточности при получении ПС 'ПС 500 кВ Усть-Илимская ГЭС'`
   - **Решение:** Запускать сервер с флагом `--nothreading`: `python manage.py runserver --nothreading --noreload`

2. **Органы требуют КЗ на противоположном конце, но все КЗ были на ответвлениях:**
   - Для органов с `exclude_branches: True` (3I0 ОТКЛ, I2 ОТКЛ, IЛ ОТКЛ, U2 ОТКЛ) нужны КЗ на противоположном конце
   - Если все КЗ были на ответвлениях, они исключаются фильтром
   - Результат: `0 КЗ` для анализа

3. **Органы требуют КЗ на ответвлениях, но они не были рассчитаны:**
   - Для органов с `requires_branches: True` (РТНП/3I0_M0, РННП/3U0_M0) нужны КЗ на ответвлениях
   - Если из-за ошибок многопоточности КЗ на ответвлениях не были рассчитаны, анализ не выполняется

### Логика сохранения результатов

Результаты анализа чувствительности сохраняются в БД только если:
1. Найдены соответствующие КЗ (`fault_calculations.count() > 0`)
2. Успешно рассчитан коэффициент чувствительности
3. Вызван метод `_save_result_to_db()`

Если КЗ не найдены, цикл `for fault_calculation in fault_calculations:` не выполняется, и записи не сохраняются в БД. Поэтому эти органы не отображаются в интерфейсе.

## Техническая реализация

### Как определяется, нужно ли проверять чувствительность

1. **Метод `_build_sensitivity_handlers()`** в `SensitivityAnalysisService`:
   - Проходит по всем записям в `SENSITIVITY_FAULT_MAP`
   - Пропускает органы с `check_sensitivity: False`
   - Пропускает органы без `fault_types`
   - Создает обработчики только для органов, которые должны проверяться

2. **Метод `_get_handler()`** в `SensitivityAnalysisService`:
   - Ищет обработчик для органа в словаре `SENSITIVITY_HANDLERS`
   - Если обработчик не найден, возвращает `None`
   - Орган пропускается с сообщением: `"Пропущен орган {name}: нет обработчика чувствительности"`

### Где находится карта чувствительности

Файл: `calculation/services/sensitivity_fault_map.py`

Класс: `SensitivityFaultMap`

Словарь: `SENSITIVITY_FAULT_MAP`

## Вывод

Не все органы отображаются в анализе чувствительности, потому что:

1. **Блокирующие органы (БЛОК)** не проверяются на чувствительность по своей природе
2. **Органы X ОТВ и X ОТКЛ** не имеют записей в карте чувствительности
3. **Орган УГОЛ БЛОК** явно отключен от проверки чувствительности
4. **Органы с обработчиками не отображаются**, если для них не найдены соответствующие КЗ:
   - **3I0 ОТКЛ, I2 ОТКЛ, IЛ ОТКЛ, U2 ОТКЛ, К МАН** требуют КЗ на противоположном конце, но все КЗ были на ответвлениях
   - **R ОТВ, R ОТКЛ** требуют КЗ типа К(3) с ненулевым I1, но такие КЗ не найдены
   - **РТНП/3I0_M0, РННП/3U0_M0** отображаются, потому что для них найдены КЗ на ответвлениях

### Решение проблемы отсутствия КЗ

**Основная причина:** Ошибки многопоточности PowerFactory при расчете КЗ.

**Решение:**
1. Запускать Django сервер с флагом `--nothreading`:
   ```bash
   python manage.py runserver --nothreading --noreload
   ```
2. Убедиться, что PowerFactory доступен и проект открыт
3. Пересчитать КЗ для текущего расчета после исправления проблемы с многопоточностью

Это **нормальное поведение** системы, когда КЗ не найдены из-за технических проблем (многопоточность) или особенностей топологии сети (все КЗ на ответвлениях, а нужны на противоположном конце).
